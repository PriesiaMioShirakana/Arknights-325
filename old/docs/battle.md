# 战斗核心

`Stronghold::Battle` 链接 `Stronghold::Core`，使用 C++23、显式 30 Hz 时间推进，没有 JavaScript、Python、网络或系统时钟运行时依赖。这里记录已实现的通用机制；真实角色内容和整局适配仍在迁移，不能据此宣称完整兼容。

## 输入与所有权

`BattleInput` 持有部署、出怪、已解析属性／技能／攻击配置、路线、DP 和时限。`WorldPoint` 的 x 是列、y 是行，完整场地 19×21；范围偏移以朝右为原始朝向。提供 `MyField` 时按地图流场寻路；省略地图时按已解析路点行走。动态地形仅通过 `SetObstacle` 修改障碍层。

`Start` 免费交错部署；`Step` 首次调用也会自动开始。`Advance` 推进固定 tick 数，`ForceEnd` 结束。推进不可重入，扩展回调中嵌套 `Step` 会记录扩展错误。`Units`、`Players` 是只读视图，`DrainEvents` 取走事件，`Result` 返回结算副本。

Battle 禁止复制、允许移动。单位以 `deque` 分段存值，数字 ID 与元素引用在动态出生时稳定；友军／敌军索引分别预留容量。`Units` 返回只读容器引用；容器迭代器不能跨会创建单位的回调保存，改用 ID／下标。移动 Battle 后不得继续使用旧视图。

## 数值、状态与 Buff

- `CombatDefinition::MyStats` 是基础值；`CombatUnit::MyStats` 是 Buff／状态修正后的当前值。固定数组汇总加算、乘算、独立闪避源、穿透、受伤／治疗倍率等。最大生命变化保留生命比例。
- `AddBuff` 支持替换、延长、叠层、独立实例和保留；`RemoveBuff` 可按编号或 key 移除。周期、到期和移除效果区分，遍历使用编号快照以容纳回调中的删除。持久 Buff 在友方倒地时保留。
- `ApplyStatus` 的结构化重载支持值、来源、位置、免疫绕过和已抵抗标记；处理抵抗、寒冷转冻结、重量影响、强弱效果接续、麻痹层数、选择／治疗／SP 限制。传统 seconds 重载仍接受 0–3600 秒有限值。固定状态槽不动态分配。
- `FEAR` 与 `ATTRACT` 已接入地图路径、随机选点和路线恢复。敌方隐匿脱离阻挡后按每个 Buff 来源分别计算恢复窗口（默认 3 秒），新增来源不受其它来源的窗口影响；显式反隐、阻挡和来源移除均参与选择判断。

## 地图、位移与单位生命周期

`FieldGrid` 按值持有 19×21 地形和障碍层。SPFA、邻接顺序、代价、原地平滑及可阻挡地块偏好对照原实现；64 个目的地缓存按原淘汰规则复用。BLOCK 是硬障碍，CRATE 是高代价格，敌军被迫穿过时可接触并攻击对应装置。

`Push`、`Pull`、`PullToFront` 和 `Displace` 包含力／质量、方向修正、特殊推力表、急停半径、逐 0.1 格碰撞检测。静态刚体、失衡免疫和共享首领不位移；普通 BOSS 阶级本身不免疫。移动后解除阻挡、结束攻击停步并重建路径。

`SpawnToken` 接收已解析召唤物定义、所属干员或玩家、持续时间、初始生命；`SpawnDevice` 创建中立友方装置；`SpawnEnemy` 同步生成动态敌人，可排除击杀／总数统计。初始装置由 `MyDevices` 提供。敌军行动阶段中新生的敌军下一帧行动，友军召唤沿原顺序当帧行动。

`Retreat`、`Redeploy`、`Relocate` 和 `MoveRedeploy` 分别表示撤退、再次部署、保留状态换位及触发部署效果的移动。倒地干员占位，自动回到身体所在格；倒在其它棋子初始位置时尝试回到自己的初始位置。`SetDownAtHome` 支持原项目明确保留的回家倒地规则。过期召唤物与被毁装置不自动重部署；装置移除时清除对应障碍层。

## 特殊地形、地图数据与装置

`TerrainRules` 使用适配阶段解析好的数值。沼泽在入格时和每秒叠层，重型敌人每次两层；排气格栅给友军隐匿；深水给地面敌人减速／减攻速和无来源持续伤害；活性源石离开后继续持续，在格中刷新剩余时间但不重置伤害节拍。气流按照部署方向或敌人的实际移动方向计算，停步保留上一帧的移速效果。地形伤害携带 `DamageTags`，区分环境伤害与深水持续伤害。

`SpawnTurret` 以别名幂等激活“​​双眼皮”。绝对射程不能随炮台选址旋转；场外炮台优先选择不可部署且不在地面路径上的空格。炮台在普通弹道阶段之后行动，攻速与命中脆弱按所属玩家最高盟约层数计算并封顶。`SetBondLayers` 在修改时更新最高层缓存；它记录层数，具体盟约效果由内容模块实现。原始阻隔工事在敌人阻挡一个攻击间隔后被破坏，无攻击敌人也有效；延迟动作到期重新检查存活与阻挡关系。

链接 `stronghold_catalog` 后，`ReferenceEnemy(id).MakeDefinition()` 提供 249 种敌人的基础属性、攻击动画、免疫与体型。天赋、技能黑板、技能 SP 和说明保存在静态只读记录中；这个接口本身不安装专有天赋／技能。`ReferenceBattleStage(id).Apply(input, rect, overrides)` 提供 13 张实图的地形、气流、平台和装置。`DeviceOverride` 支持全场或所属玩家的别名开关，玩家设置优先。`MyRightHalf` 与镜像部署分开，以支持联防右半场不镜像的情况。

地图适配保留原项目的装置时序：默认工事先于干员部署；关闭的默认工事仍产生已移除的单位记录；开启隐藏工事和炮台发生在干员部署之后。平台初始高度与地图卡的部署高度覆盖分开，保留原 `relocate` 与 `moveRedeploy` 的行为差别。原 sim 未实现的旧赛季水上平台、沙尘暴、草丛等只保留数据；不添加自行猜测的规则。

## 攻击、伤害与治疗

巨型单位用 `HitArea` 矩形判定格子范围和体表距离；阻挡、移动、弹道落点及中心溅射仍用单位中心。占格查询用固定范围直接计算，无临时容器分配。索敌优先级包含精英／首领、质量、攻防、血量比例、远近与是否元素爆发等原规则。

普通攻击支持多目标、全范围、多段、拆分伤害、跟踪弹道、溅射、连锁、命中状态、治疗链及元素治疗。索敌保持稳定顺序。弹道保存发射时攻击配置，在命中时读取 ATK；旧生命的弹道不命中再部署生命。带溅射的弹道在目标消失后飞至最后位置，其它弹道取消。

`ForceAttack` 支持显式目标和不消耗技能弹药。嵌套攻击各自使用可复用工作区，扩展中的强制攻击不会覆盖外层目标列表。普通连锁以距离／出怪序号选取，治疗链按相邻九格、生命比例／最后部署优先，可经过满血单位。

`DealDamage` 处理闪避、穿透、伤害倍率、首领限伤、频次生命、次数及生命护盾，再结算 HP。完全被盾吸收的有效命中仍走受击 SP。耗尽的纯 Buff 护盾被移除；附带属性或 flags 的 Buff 保留。`LoseHealth` 绕过减免和护盾，不回复受击 SP。`Heal` 返回实际恢复量；`HealOptions` 区分自愈、再生、穿透禁疗、忽略 HEAL_FREE、静默和溢出盾。再生通知扩展但不受普通治疗倍率／改量影响，溢出盾按最大生命封顶并按定义时长到期。

扩展可在 HP 扣除前降低伤害，在致命阶段阻止死亡，或在击杀前恢复生命。无来源伤害的回调 `MySource` 为 0，`MyCredit` 保留统计归属。`BattleInput::MySharedBoss` 借用宿主持有的 `SharedBossPool`。宿主串行推进共享血池的战斗，BOSS 出怪标签绑定血池；扣血记录实际血池贡献，按各实体当前最大生命同步显示比例。池空结束所有仍在推进的战斗，提前结束的战斗保留结束时血量快照。首领阶级、BOSS 出怪标签和共享血池身份分别处理。

## 技能与 SP

`SkillDefinition` 与 `SkillState` 是值类型。支持持续、弹药、瞬发／下一次攻击、充能、被动、切换技能；技力来源有时间、攻击、受击和显式授予。`GainSp` 表示回复，`SetSpTotal` 表示直接修改总技力；满充能时显示条保持满值。零费用技能仅在部署时获得充能。

眩晕不暂停时间 SP；阻回和运行中的持续／弹药／切换技能暂停回复。技能攻击不恢复攻击 SP，最后一发弹药也遵循此规则。默认、SP 满、初始范围、技能范围、自定义范围、活动范围、全场、受击和禁止自动释放策略已接入。手动技能的自动操作遵守初始／施放后 3 秒冷却；显式 `ActivateSkill` 可绕过自动策略。

`EndSkill` 先关闭活动状态，再发出 `SKILL_ENDING`，此时属性和范围修正仍在；随后移除修正并发出 `SKILL_END`。收尾回调重新激活技能时，旧施放不能移除新施放的 Buff。`AddSkillAmmo`、`ExtendSkill`、`AddSkillCharge` 和费用倍率接口供内容实现使用。`SetSkillTrigger` 可切换策略和范围；`AddSkillTriggerRange` / `UpdateSkillTriggerRange` / `RemoveSkillTriggerRange` 管理额外触发区。范围使用固定格掩码，或稳定单位 ID 的实时射程；不保存捕获 Battle 的回调。`MyOnlyDuringSkill` 支持平时停止普攻、技能期间行动。

## 元素机制

`DealElement` 处理元素损伤量表；`DamageType::ELEMENTAL` 处理爆发造成的 HP 元素伤害，两者分开。支持神经、侵蚀、灼燃、凋亡及原项目兼容用 necrosis 的双方规则。普通量表 1000，敌方首领 2000。爆发期间全部量表锁定，到期或移除冷却 Buff 时全部清零。

`ReduceElement` 默认分别降低每种量表，也可指定元素；锁定期间无效。`ElementView` 输出当前图标、满度和冷却时间，固定按官方元素顺序处理相同满度。凋亡包括我方阻回／静默／总 SP 流失和敌方逐秒减弱的虚弱。爆发伤害不继承填充者的增伤和穿透，但保留统计归属。

## CUSTOM 注册

只有扩展标签使用 `CUSTOM_OPERATOR`、`CUSTOM_ENEMY`、`CUSTOM_BUFF`、`CUSTOM_BOND`、`CUSTOM_BOND_EFFECT`。PHYSICAL、STUN 等已有枚举不改名。内置单位不建立派生对象；自定义实例用一个类型擦除入口，CRTP 在编译期移除未实现的钩子。

```cpp
struct ExampleOperator final : Stronghold::CustomOperator<ExampleOperator>
{
	void OnDeploy(Stronghold::Battle& _battle, Stronghold::ContentEvent& _event)
	{
		_battle.AddShield(_event.MyHandlerUnit, Stronghold::Shield{.MyHealth = 100});
	}
};

Stronghold::ContentRegistry registry;
const auto custom = registry.Register<ExampleOperator>("example");
registry.Seal();
// input.MyContentRegistry = std::cref(registry);
// input.MyPlayers[0].MyUnits[0].MyDefinition.MyContent = custom;
```

对应基类还有 `CustomEnemy`、`CustomBuff`、`CustomBond`、`CustomBondEffect`。注册表必须在建局前 Seal，且比 Battle 活得更久，期间不可移动或赋值。实例由 Battle 独占，每个单位／Buff 独立创建；回调自删除延迟到最外层回调返回。重复 ID、错误类型、未封存表会被拒绝。扩展异常记录于 `ContentErrors`，达到错误预算后结束本局。

`ContentEvent` 给出事件参与者、处理器所有者及类型化参数。部署、攻击／命中、技能、SP、伤害、状态、Buff、元素和结束均有钩子；详见 `content_registry.hpp`。回调不得保存事件引用。

仍待实现：尚未覆盖的专属干员／召唤物、战斗装备与盟约／特质、分支首领与敌人脚本、机器人与离开控制，以及协议快照和完整对局回放。后续章节记录已完成的准备内容、职业、联防和本地阶段宿主；完整范围以 [迁移进度](migration-progress.md) 为准。HTTP 和集群继续排除在当前范围外。

## 联防继承与初始召唤物

`AllyDeployment::MyKind` 区分干员和棋盘召唤物，`MyOwnerPieceUid` 解析同玩家的拥有者，允许输入中召唤物在先。`MyDeferred` 保留格子且等待显式 `Redeploy`。部署分干员、召唤物两个阶段，每阶段按列／行排序并交替处理玩家。部署回调带入的召唤物也在初始仇恨重排中；`MyAggroSequence` 用于仇恨，`MyDeploySequence` 继续作为一次部署的身份。

`MyCarry` 接收上一场生命比例、包含充能的 SP 和退场标记。生命继承只作用于干员，召唤物满血；活动技能、弹药和 Buff 不继承。部署前恢复 SP，部署回调后再写回，避免赠送重复叠加。初始部署阶段由拥有者带入的棋盘召唤物同样继承；之后的普通部署不再使用继承值。

退场标记先完成初始部署，再以 `FORCED_EXIT` 退场，不增加阵亡或击杀计数。`MyAllowDead` 允许开场 Buff 作用于倒地干员；战斗开始回调结束后按更新的再部署倍率重算计时。`Result().MyPlayers[].MyUnitsEnd` 是独立值快照，包含棋盘干员和召唤物，排除没有棋盘 UID 的动态召唤物；`Carry()` 可直接生成下一场输入。

## 波次与类型化定时动作

`ReferenceWave(id)` 提供主路、额外路线、巡逻索引、出怪组、分支动作、敌人覆盖和装置开关。`MakeSpawns` 将主出怪组按时间稳定展开，解析区域坐标和出生半场归属；`Enemy(id)` 提供覆盖后的静态敌人定义。槽位替换和阵营随机选择现由 `WaveGenerator` 执行；原 `match/waves.js` 未执行模板 group/pack 的加权抽取，当前保持相同行为，不另行发明规则。首领分支内容脚本仍待移植；`ACTIVATE_PREDEFINED` 保留为动作元数据。

`StartColdWind` 按间隔触发全场或指定半场的寒冷，持续时间每次读取盟约层数；可查询阵数及取消。同一优先队列还处理召唤物到期和工事破坏。每帧先收集到期批次，再执行动作；回调中新建的零延迟动作留到下一帧，周期动作保留序号，单帧追赶有预算。所有任务保存类型化值和 ID，可随 Battle 移动。

## 干员、补位与自选数据

`ReferenceOperator(id).Loadout(skillIndex, moduleId)` 查询构建时组合好的属性、特性、天赋、技能黑板和范围；非法技能／模组分别退回默认。第三个参数开启补位，存在补位时忽略其它选择；补位仍使用原棋子的身份、盟约和特质。`MyStandIn` 可查询是否存在补位。

`OperatorRecord::Diy(characterId, skillIndex, moduleId)` 仅允许该阶级的有效自选。自有干员必须指定技能，原型可省略锁定选项；显式选择与锁定值冲突会被拒绝。`MyDiyChoices` 提供不可变可选表；这里包含数据层允许的模组，准备层还需按原协议过滤仅其它玩法生效的模组，并检查持有、跨槽位去重和内容脚本是否可用。每个选择保留精锐模组配置，即使当前普通形态尚未激活该模组。

`ReferenceToken(id).Variant(owner, skill, module)` 支持棋子拥有者及原始回退规则；`DiyVariant(choice)` 按自选干员和训练状态查表，无匹配时使用顶层默认。召唤物生产来源、数量、基础异常和自动销毁时长分别保存，不能把仅展示用召唤物当作可部署奖励。

当前静态表包含 266 条干员记录的 1,131 个技能／模组组合、110 条补位、4,824 个自选配置，以及 60 类召唤物的 876 个普通查询变体和 873 个自选变体。全部记录与原 `DataSource`／归一化函数逐字段对照，另外覆盖 67,860 次普通拥有者查询和 289,440 次自选召唤物查询。`AllyRecord::MakeDefinition` 要求调用方显式提供攻击配置；它构建独立拥有的基础身体，并携带下文已实现的职业状态配置；专属天赋、具体技能和其它职业脚本仍需逐项移植；通用技能回退见下文。


## 职业基础攻击与状态

`AllyRecord::MyBaseAttack` 在构建时按原 `resolveProfile` 解析职业、分支、黑板和数据覆盖；主目标条件倍率、群攻／阻挡目标数、溅射、连锁、治疗距离与命中状态均采用固定值配置。对空、未被自身阻挡、远程与正前方倍率只作用于主目标，不能传递给溅射或连锁。正前方支持自定义范围和巨型身体；连锁按受击体积进入跳跃半径，再按中心距离排序。阻挡容量下降立即释放最后建立的超额阻挡。

`MyProfessionTraits` 当前包含猎手、驭械术师、秘术师、阵法术师、执旗手和伏击客。`MakeDefinition` 将这些参数复制到单位定义；状态保存在所属 `CombatUnit` 内，不创建虚函数对象或跨对局静态状态。猎手停止攻击至少一秒后累积装填进度；驭械术师在命中时累计同一目标倍率；秘术师在无目标且可攻击时蓄能，并将储能附在下一次攻击的首个目标弹道。阵法术师随技能切换防护，执旗手在技能开始时释放阻挡，伏击客的闪避／嘲讽 Buff 持久保存。

普通重新部署清空秘术师储能，免费移动保留；猎手在两类部署中均装满，驭械术师目标记录沿用原实现。攻击配置数据与所有干员／召唤物组合逐项对照；战斗差分另覆盖 32 个基础攻击场景（4,800 帧）和 12 个状态场景（6,480 帧）。这些结果不代表其它职业和干员技能已经完整实现。


职业效果现另外支持武者／收割者自愈、咒愈师伤害回复、冲锋手击杀费用、怪杰非致命流失、行商费用、解放者蓄力和吟游者再生。普攻以 `MyIsAttack` 标识，生命流失以 `HP_LOSS` 标识；`MyTraitAlly` 可为咒愈师指定治疗目标。收割者技能伤害的回复次数以同一个逻辑帧封顶，普通攻击另按一次攻击的目标数计算。原 `professions.js` 的咒愈师实际只排除元素损伤／元素伤害，未排除有来源的生命流失；当前按这一实际行为对照，未自行修改规则。

职业周期任务复用战斗的类型化优先队列，离场时暂停实际效果而非重置周期；定时器属于每局状态。`AddDp` 在上下限内修改费用；`MERCHANT_PAY` 允许 CUSTOM 修改或取消支出，`BARD_REGEN` 允许修改指定目标的再生值。吟游者提供有时限的生命回复速度 Buff，离开射程或停止作用后自然失效；多名吟游者使用不同来源键叠加。新增 8 个职业效果场景、3,600 帧独立 JS 对照。


回环射手的去程／返程均为值类型弹道，返程期间不能自动攻击，死亡或移动到新部署身份后旧弹道不能归还；`BOOMERANG_CAUGHT` 通知包含攻击编号、技能标记和落点，供后续回收类技能使用。投掷手余震复用统一定时队列，逐次读取来源当前攻击力，来源离场不取消已预约伤害。炮手有阻挡时只选一个阻挡目标并切为即时命中，保留原实现的溅射。新增 3 个弹道职业场景、900 帧对照。


策士在部署时通过 `FindTacticalPoint` 查询初始射程内的可站立地块，先排除活单位、倒地体和未部署棋子的预留位置，再按地面道路、切比雪夫距离和朝向局部坐标选点。`BattleInput::MyGroundRoutes` 接收波次层已选中的非飞行道路；`WaveRecord::MakeGroundRoutes` 处理已使用的道路索引及无有效地面索引时的回退。道路缓存按地形版本失效，包含平滑寻路折线经过的地块。援军使用本体基础属性；已有援军存活时不重召，主目标被自己的援军阻挡时应用职业倍率。四个朝向与道路／障碍／重召共 12 场、2,160 帧与 JS 对照。巡空者的阻挡飞行能力安装为持久 Buff。

傀儡师的本体／替身和切换标记属于单位值状态。普通 CUSTOM 不死事件先处理，之后职业才决定转替身；切换期间生命流失也不能击倒，强制眩晕／冻结／睡眠仍被拒绝。切换结束写回满血不视为治疗；提前驱散切换 Buff 不补满血。替身 Buff 到期或移除都回切，本体和替身切换均保留普通外部增益与护盾、清状态并结束非被动技能。`EnterDoll` 提供内容主动切换入口，`DOLL_SWAP` 提供扩展通知。替身最大生命按所选技能／模组的自身替身数据在构建时解析，覆盖普通、补位和自选配置。8 场、6,000 帧验证了这些生命周期，包括替身死亡、回切中流失和重新部署。


## 比赛波次、悬赏与联防结算

`WaveGenerator` 借用构建时配置中的 span/string_view，配置必须覆盖生成器及计划的消费期。模式视图本身按值保存，允许传入临时视图。`Setup` 的阵营排程使用从主流状态派生的随机流；阵营选择、顺序和附带敌人取样与原实现一致。替换数量在原规定的步骤显式舍入为 float32，并按半偶数规则取整。`WithBounties` 插入单位后重排宿主自身的时间；首领场传入 `_retimeOwn=false`，只追加悬赏而保留原动作时间；`BuildUnite` 依原模板宿主及来源玩家分组，以半秒错峰。`MakeSpawns` 应用倍率后保留出生元数据，不在 Battle 内再次乘算。

战斗结果保留每个漏怪的原始倍率、悬赏 ID、来源、生命值损耗和计数标签，以及超时时的全部未出生队列。`MyPerfect` 只因计数漏怪或首领漏怪失效。悬赏资金先归击杀者玩家，其次为参战的原悬赏拥有者，最后为击倒位置所在半场；重复致死不重复支付。`COINS_GAINED` 事件携带玩家索引，`OnEnemyLeak` 在敌人自己的扩展处理器释放前通知，超时只记录漏怪而不触发该通知。

`PlanUnite` 选人时按部署数、激活盟约、存活数、座位排序；只在选中的帮助者间再加入盟约层数决定迎敌顺序。未知敌人保留为不能重新进场的损失。`PlanUniteRelay` 只消费上一联防残留；未出生的同名敌人通过时间、来源和多重集合顺序取回实际场地输入中的倍率与赏金。`UniteSurvivors` 以来源玩家统计计数漏怪、未出生队列和不能重进场者，每个单位计一次，不使用其 lpr 作为普通回合扣血数。

`RoundLedger` 持有每位玩家的生命、统计、悬赏期限及待发资金，原子接收同回合战报。最终扣血按回合上限封顶；完美悬赏只看本场普通战斗，联防击杀资金另计。启用实验救援时，有资格的真人帮助者需至少 11 LP，消耗 10 LP 使待救援队友以 1 LP 回归，每个被救者整局仅一次；窗口以外部逻辑时间推进，持续 15 秒。最终淘汰才清空持有；`CommitToPreparation` 将全体玩家结果一次性送入经济会话，再清空账本待发资金。该模块尚不执行内容层 onBattleResult；盟约层数通过独立 `BondLayerLedger` 同步，宿主的完整阶段机仍待接入。


## 最终攻势与选秀

`FinalAssault` 在最终攻势开始时保存玩家生命和激活盟约层数快照，按座位配对；隐藏关沿用剩余团队生命，重置该关血池、伤害档位及超时计数。团队生命以最大余数法回写个人显示值，余数相同先分给低座位，不触发普通回合的个人淘汰。隐藏资格使用严格大于的层数和生命阈值；实验扩容只在合作模式 5–20 人时采用人数 / 4 的缩放。隐藏关失败保留已完成最终攻势的整局胜利。

`BattleInput::MyFinalAssault` 直接借用控制器；每次首领命中和非超时漏怪立即提交，不依赖事件队列的消费频率。`LoseTeamLife` 为首领技能提供同样的入口。首次终局判定封存血池，因此团队生命先归零后的迟到攻击不会继续入账。独立使用 `Pool()` 写入伤害时，调用者必须在每次逻辑操作后调用 `Observe()`。控制器禁止移动；所有借用它的战场必须先销毁，再调用 `BeginHidden`。

`BossBattleGroup` 持有配对战场并借用控制器；以 `Step` / `Advance` 推进 30 Hz 时间，普通界面倒计时不终止首领战，超时按完整实秒扣生命，保留原执行器 3700 游戏秒的硬上限。组完成后可读取值类型战报。宿主异常隔离、客户端接管、网络报告预算和传输仍不在这个本地推进器中。

`RoundLedger::SettleBoss` 与普通结算共用回合去重，接收团队 LP 分摊和本关首领伤害，将击杀悬赏资金推迟到下轮备战并消耗悬赏期限；首领阶段不额外支付完美悬赏。它不替代内容层 `onBattleResult`。

`StrategyDraft` 保存战略高亮、跳过次数和默认回退；`SpecialDraft` 按卡槽编号分配同名卡片，接受外部逻辑时间，超时仅在实际选卡时消耗随机流。后者返回 `ChoiceAward`，奖励执行由宿主负责；卡片由 `GenerateChoices` 生成；内容奖励由 `PreparationContent` 执行；完整宿主尚待组合。两个模块均不调用系统计时器。`ReferenceMatchMode` 将 config/bands/bosses 的真实规则生成成不可变表，包括模式允许的战略及其基础生命、回合时间和首领基础生命；不是运行时 JSON 解析器。


`GenerateChoices` 读取不可变 `ChoiceGenerationRules`；`ReferenceChoices` 在构建期编译 choices/items/enemies/effects。悬赏按原分组权重和缺失组合规则生成，初期偏好阶级先填，后期先补巨型敌人再按系列限制填充；商店和战术卡允许独立重复抽取。只有可作用盟约全部不可用的战术卡被过滤。合作扩容局补足到玩家数 + 2（最多 22）张，悬赏只重排本次已选组合。返回卡片文本拥有其存储，选秀标题、事件 ID 和悬赏敌人 ID 借用静态表。低频生成采用随机流副本，成功时提交，无卡可选也提交原版已经消费的随机数；异常不改变调用方随机流。


## 盟约成员与层数收益

`BondCalculator` 借用已解析的规则，复用成员计数缓冲区；`PreparationBondCalculator` 将库存投影为成员输入，并可接收本局自选/自定义干员的成员覆盖表。临时栏不参与人数；普通/精锐按基础 ID 去重，助力上档按基础 ID 加精锐标记去重，绝技计算场上全部精锐副本。调和只给确有场上成员的核心盟约增加一人。装备成员关系需要变形同构体和赋予指定盟约的装备同时存在。禁用盟约仅在显示列表末尾保留人数，不进入战斗状态。

计算结果 span 在下次 Compute 前有效，长期保存应复制；规则及字符串由调用方保持生命周期。`View(gains)` 在副本上加入未入账的收益并重新排序，持久值不变。内置规则、干员成员关系及装备元数据由 `generate_bonds.py` 编译成静态数组。

`Battle::AddBondLayers` 分开维护实时层数与 `MyLayerGains` 累计收益，先触发 `LAYER_GAIN` 修改钩子，再按 999 上限截断；已经满层时不触发钩子。没有实时盟约条目的简化输入使用本场累计收益作为上限基数。`LayerGainOptions` 可携带来源、原因和格子，击倒当刻仍保留来源格子；这些视图仅在同步调用期间借用。CUSTOM 扩展使用 `OnLayerGain`，普通内容保持直接调用。`LAYERS_GAINED` 事件以玩家索引和其累计收益表中的稳定索引标识盟约，避免给每条战斗事件附带字符串分配。

普通战斗默认开启层数增长，首领战默认关闭；联防必须显式设置 `MyLayerGainsEnabled=false`，`BossBattleGroup` 强制关闭。结算钩子允许增加层数，已完成的结果快照会反映累计值。`SetBondLayers` 用于修改实时值，不代表收益，不推进累计表。

每位玩家的 `BondLayerLedger` 在 `BeginRound` 清空本轮水位而保留持久层数。`Synchronize` 接收普通战斗的累计报告，向下取整后只入账新差额，先推进水位再调用效果，因此重复、乱序以及效果重入都不会重复发放。到上限后仍推进水位，防止后续层数降低时重放旧收益。该账本不替代场次身份验证；宿主必须校验当前回合/战场、玩家存活与允许增长的阶段，再送入报告。


### 玩家配置与准备卡池

`PlayerRoster` 接受类型化技能／模组选项、自选槽位和未持有列表。请求中的临时字符串不会被保存：成功结果引用编译期目录；非法技能／模组整体拒绝且旧状态不变，自选和未持有列表对语义无效项逐项丢弃。自选冲突按原数据槽位顺序解决，普通和精锐形态由同一选择解析。机器人保留默认配置。宿主负责仅在原版允许的开局配置阶段调用；自选必须提供实际可执行的角色 kit 白名单，静态身体数据存在并不代表其技能已经实现。

`ConfigurePreparationRoster` 将配置转为经济核心的独立库存和部署类别覆盖；`ConfigureRoster` 只接受开局且尚未发放棋子的状态。未填入自选槽位不能作为棋子发放。被禁用的已填槽位仍可识别自己的身体，但库存为零；内容强制赠送时可获得不占用库存的副本。普通商店和合成奖励在共享池之后按槽位顺序扫描玩家库存，服从各自的商店等级与等阶筛选；物品商店的等阶占比仍只使用共享池。晋升、合成、销毁、变形、过期及淘汰统一通过玩家副本路由归还，守恒检查同时覆盖共享池和独立库存。

`PlaceableTokens` 查询身体配置可发放的召唤物，调用方缓冲区清空后复用。预设干员的数量遵循原 `GameData.placeableTokens`，自选另外读取已生效模组的部署上限覆盖，最多九个；数量与战斗技能中的召唤次数分开。补位和未填自选不发放召唤物。`MakeSummonCatalog` 将选择解析成会话借用的只读目录；目录须覆盖会话生命周期，不能在借用期间移动或赋值。准备阶段的堆叠、棋盘范围与拥有者回收已接入。


### 准备阶段召唤物

`ConfigureSummons` 仅允许开局且未发放棋子时调用。召唤物由拥有者发放，不能通过普通干员赠送接口凭 ID 创建；`MyOwnerUid` 关联拥有者，手牌／临时栏使用 `MyCount` 堆叠，棋盘上每格一只。堆叠拆分只在确实留下原堆叠时分配新 UID。移动拥有者回收其场上召唤物，撤回／出售／销毁／合成拥有者清理全部所属召唤物；精锐结果已部署时按新配置发放。每轮开始只补齐缺失数量。

射程由玩家最终技能／模组／补位／DIY 身体解析，并按拥有者朝向旋转。转向导致召唤物越界且无容器空间时提前拒绝；晋升或布局改变留下的越界召唤物会被收回，完全满仓时移除并在下一轮补齐。召唤物与自己的拥有者交换时用拥有者交换后的射程判定。

棋盘使用固定数组存格子，同时用固定索引数组保存原 JavaScript Map 的键插入顺序；召唤物回收和补发依此顺序，合成选点仍用棋盘阅读顺序。原版满手召唤物撤回失败会删除再插回棋盘键，位置和资金不变，但后续回收保留的堆叠 UID 可能改变；会话有意保留这个例外，未把它当成完全无状态变化的失败。


### 内容经济与机变奖励

`PreparationContent` 借用经济会话、结算账本和静态奖励规则，持有玩家的盟约层数、机变效果、装置覆盖和独立引用序号。传入的成员关系字符串/盟约 span 必须覆盖执行器生命周期；`PlayerRoster::MakeContentPoolRoster` 返回的元素引用静态编译数据，可在开局后缓存复用。调用 Apply 的权限和选卡凭据去重属于对局宿主；显式再次调用表示再次获得同一卡片。

一次团队奖励按选卡者优先、其余存活座位顺序消费内容随机流，成功后统一提交。购买晋升次数和免费刷新保存在经济会话，悬赏保存在 `RoundLedger`，后续结算消费期限；赠送干员仍需要库存有至少一份，精锐赠送允许只取当前剩余份数。`OnPreparationEnd` 在准备期限清理之后、库存 EndPreparation 之前重算手牌条件，普通栏和临时栏中的道具/召唤物堆叠也各计一张。

内容池抽取不预占副本。显式干员列表可以包含共享池之外的有效定义，额外 DIY 库存仍单独检查；自动内容池按副本权重抽取且没有商店解锁门槛。装备零权重池消费一次随机数并回退到最后一项，干员零权重池不消费随机数并回退到第一项，此差异来自原版两个入口，不能合并成一种默认抽取。


### 机变战斗规则

`MakeChoiceBattleEffects` 将已保存的机变引用转换成战斗自持的输入；字符串和修正数组不依赖准备执行器寿命。`BattlePlayerInput::MyHandUnits` 仅作旧输入的手牌条件回退，显式准备判定优先。同排条件只在开战时统计已部署且存活的所属干员，但生效的再部署修正也施加给开局被强制退场者。

机变普通属性增益持久保留，满血增益在受伤后立即、治疗后的下一 tick 同步；自愈作用于干员和召唤物，每次 HP 伤害触发，元素量表和生命流失不触发。敌方属性修正按所属半场及普通／精英／首领位阶在出生时应用。重复选卡以不同引用键叠加，核心直接分派，不经过 CUSTOM 注册表。


### 当前暂停点：消耗型装备执行

`ReferencePreparationItems()` 将 `builtinMeta.js` 与 `items/meta.js` 使用的道具黑板编译为 `PreparationItemRule`，保留普通／进阶差异、多个效果的顺序、法术范围与装备赋予的盟约。运行时不需要解析 JSON。规则表包含 115 份道具记录、34 份准备效果定义；其中 24 个消耗型装备配置已接入 `PreparationContent`。法术和普通装备持有钩子的后续实现与验证范围见下文。

`PreparationContent` 的构造函数末尾接受道具规则 span；旧的机变调用可省略。客户端准备命令改由 `Execute(command, random)` 进入：消耗型装备使用经济／内容／随机流副本，成功时一起提交；其余命令转交 `EconomySession::Execute`。无对应效果规则时拒绝使用。资金、层数、库存、UID 和随机流在拒绝或异常时均回滚，装备已满时被替换的物品也恢复。消耗品在效果期间仍占原手牌／临时槽；不能提前释放槽位改变满仓发放结果。携带者可能被合成或销毁，后续操作通过 UID 重新查找。

已执行盟约之币／骑士储蓄罐、随身身份牌、紧急调度券、精打细算／见钱眼开玩偶、简易通讯机、人事部文档、博士投影、拟态物质、寻呼模块和信标的普通／进阶配置。紧急调度券只清除成功发放的商店格；拟态在已有两名初始干员但库存耗尽时不给替代奖励；特殊刷新不重复干员。身份牌与抽取读取替换后的装备盟约，层数沿用同一份 `BondLayerLedger`。

宿主每轮按以下顺序组合，不能用默认直接开启准备的 `BeginRound(round)` 代替：

```cpp
economy.BeginRound(round, false);
auto receipts = content.OnRoundStart(random);
// 在这里完成机变选卡及奖励，再开放准备操作。
economy.BeginPreparation();
auto changes = content.Execute(command, random);
```

`OnRoundStart` 只允许 `ROUND_START`，同回合重复调用会抛出异常且不修改状态。普通博士投影只有仍装备在原携带者上才在回合开始销毁并晋升；棋盘按阅读顺序处理，之后是手牌／临时区，再执行持续效果。持续收入与信标保存在内容所有者，`ItemEffects(player)` 返回状态副本。先处理存活玩家，再处理淘汰者留下的信标；全体效果共用一次事务。

信标先回收携带者，生成同阶、不重复且可向低阶补足的选一奖励，按实际盟约成员数选择存活队友，同分消费一次随机抽取。`ChoiceRewardPlayerConfig::MyInactiveBonds` 由宿主传入模式禁用盟约；成员计算采用玩家自己的 roster，含装备赋予、调和、助力、手牌计数规则。赠送保存原始普通／精锐 ID，DIY 不赠送；接收者淘汰时重新选择，无队友时丢弃，库存或容量不足时保留到下一回合。赠送者淘汰不撤销信标。此模块尚不执行其他内容提供的动态盟约人数加成。

新增差分安装真实 `registerBuiltins` 和道具 `registerMeta`，保留实际盟约重算，关闭专属干员／盟约回调和召唤物。覆盖 24 个配置、三个种子、指定／默认替换、精锐拒绝、满仓、库存不足、拟态合成、晋升阅读顺序、DIY 和双方淘汰；逐操作比较经济、库存、装备、层数、持续效果和随机流，并检查副本守恒。独立原生测试验证多效果拒绝、溢出回滚、非法规则和回合重复调用。它们不代表完整宿主或所有道具联动已经兼容。

敌方治疗使用最少 1 格的范围，按出生遍历顺序选择生命比例最低的其他敌人；同血比不另行排序。无前摇、弹道或攻击停步，不经普通伤害攻击钩子。隐匿状态不是隐藏离场，仍可被友方治疗；共享血池首领被排除。禁疗不改变选择器，选中后治疗可失败且仍进入冷却。12 场／2,160 帧与原版治疗 AI 一致。

本轮 Linux x64／GCC 14.2.1 修改前 59/59、修改后 61/61 项通过，日志为 `build/gcc14-debug/baseline-tests.log` 与 `build/gcc14-debug/preparation-items-tests.log`。新增功能尚未重新验证 MSVC、Clang 或 macOS；此前 Windows 59 项的历史结果不作为本次跨平台验证。三种法术、销毁传递和上述持有钩子已在后续实现，见下节；专属内容继续迁移。最终统一必要注释复核仍安排在全部功能完成之后。


## 法术与持有装备

`UseArt` 通过 `PreparationContent::Execute` 提交。画中乾坤按朝向依次查找范围内的棋子，复制干员后才读取仍持有的装备，因此合成消耗原棋子时不会多复制一套装备。装备复制引发进阶时保留在手中；只有仍为同一装备 ID 的副本才自动穿戴。悬赏法术先洗牌对应池、再从前三项抽取；空池按阶级和完美／击杀类型回退，过滤模式禁用敌人。销毁物品的传递按存活玩家座位循环，接收者满仓时丢弃，不使用信标的跨回合重试规则。

商业包装方案累计出售次数，突变细胞在战后按携带者的下一阶精确抽取，天师古鼎在获得干员时检查同盟约／调和、配套装备和每回合收益上限。计数属于装备 UID，转移携带者保留次数，装备合成后的新 UID 重新计数。内置回调通过只存在于事务期间的类型化桥接调用；未安装内容的经济会话保持独立。

可信内容赠送和变形应使用 `PreparationContent::GrantPiece`、`ApplyInventoryEffect`，让获得干员的钩子与库存变化一起提交。每轮 `BeginRound(round, false)` 后调用一次 `OnRoundStart`；战斗结束后、淘汰提交前，逐玩家调用一次 `OnBattleResult(player, round, random)`。重复战后调用会被拒绝。`SynchronizeLayers` 接收本轮普通战斗的累计层数，通过水位去重；宿主不提交联防／首领阶段的层数收益。

新增法术差分覆盖 33 个场景、8,934 个逐操作快照；持有钩子差分覆盖九种模式、27 个场景、9,018 个快照。法术失败遵守本项目的原子命令约定：原 JS 在满仓复制失败时仍增加 UID 和获得次数，差分中显式归一化这两项失败记账，成功行为按原版比较。原生测试另验证嵌套效果失败时库存、随机流、资金和收益次数一起回滚。此阶段的完整 63 项回归日志为 `build/gcc14-debug/preparation-runtime-tests.log`。

## 本地阶段宿主

`LocalMatch` 持有已移植模块的完整生命周期，禁止复制和移动，避免目录、账本、内容执行器及首领共享池的借用失效。开局沿用 setup 随机流选择地图、阵营、首领并抽取禁用盟约；零禁用数量仍洗牌。随机禁用影响卡池和 DIY 库存，模式静态禁用才控制盟约是否激活。选秀、商店、内容分别使用独立派生流。

阶段按 `INFO_CHECK → BAND_DRAFT → BATTLE_CHECK → ROUND_START → SP_DRAFT/PREP → COMBAT → UNITE/SETTLE` 推进。每轮先生成普通波次或首领配对，再按对应半场及地图卡重算合法棋盘，随后发收入、回合效果和机变奖励。全员准备后的切换留到下一次 `Advance`，允许同刻撤销准备。准备期限先清理临时栏，再采集准备条件并关闭经济阶段。

正常场使用按座位派生的种子，联防携带普通场 HP/SP 和来源信息，实验模式可以接力；首领场按配对顺序推进同一共享池，隐藏关前先释放上一关战场。`Fields`、`NormalResults`、`Ledger`、`Result` 提供只读结果；`PhaseChanges` 保存阶段及逻辑时刻。显式 CUSTOM 绑定借用已 Seal 的注册表，内置规则不经注册表。

该宿主仍在接入完整专属内容、机器人策略、离开／暂停和最终协议。原生受控战斗测试只验证流程连接；开局 JS 差分使用真实阶段方法并仅安装当前已迁移的道具／机变处理器，不等价于全内容对局验证。



### 开局位置与退场规则

调用方在创建 `LocalMatch` 时通过 `LocalMatchOptions` 指定规则，整局固定；普通战斗、联防、最终首领与隐藏关均沿用。只构建独立战场时，`BattleInput` 提供同名字段。

```cpp
Stronghold::LocalMatchOptions options{
    .MyPlayers = {{.MySeat = {0, "player-1"}}}
};
options.MyRulePositionMode = Stronghold::RulePositionMode::INITIAL;
options.MyGarrisonEffectsAfterExit = true;
options.MyRetainGrantedGarrisonsAfterExit = true;
Stronghold::LocalMatch match(std::move(options));
match.Start();
```

| 开局选项 | 默认值 | 行为 |
| --- | --- | --- |
| `MyRulePositionMode` | `CURRENT` | `CURRENT` 按实时位置；`INITIAL` 按本战场初始部署位置，影响盟约／特质的位置条件、技能自动触发、技能攻击与治疗范围及相邻效果。召唤物使用自身首次出现的位置。 |
| `MyGarrisonEffectsAfterExit` | `false` | 开启后，已部署过的干员在倒地、撤退或永久移除期间仍可提供原本要求本人在场的战斗特质，包括魔王的前方加层、相邻弹药及范围内冻结／睡眠／眩晕加层。 |
| `MyRetainGrantedGarrisonsAfterExit` | `true` | 接受者退场后是否保留获授特质。关闭则移除，本战场重部署不会自动恢复；开启则保留特质及其收益计数。授予者退场始终不撤回已经完成的授予。 |

三项可独立组合。“保留获授特质”决定接受者是否继续持有它，“退场生效”决定仍持有且原本要求本人在场的效果能否在离场期间触发。以凛御银灰授予的冻结加层特质为例：

| 保留获授特质 | 退场生效 | 接受者退场期间 | 本战场重部署后 |
| --- | --- | --- | --- |
| 开 | 关 | 保留特质，暂停冻结加层 | 恢复触发，沿用收益上限 |
| 开 | 开 | 保留特质，继续冻结加层 | 继续触发，沿用收益上限 |
| 关 | 关或开 | 移除特质，不再触发 | 不自动恢复 |

运行时区分自身特质与获授特质；同名自身特质不会被撤销，重复授予不叠加或重置计数。关闭保留时，先结算本次退场事件，再停用获授监听与属性；移除再部署倍率后按剩余属性计算本次再部署时间。已获得的盟约层数不回退。该选项覆盖所有战斗授予，包括开技能／击杀／部署加层及读层属性，不只冻结类特质。

退场后的范围源按所选位置模式计算：实时模式使用退场前的位置，初始模式使用初始部署位置。额外层数仍检查来源、玩家、盟约及特质条件；周围目标人数继续只统计在场干员，从未部署的等待单位不会提前提供效果。自身特质及保留下来的获授特质在重新部署时沿用原实例和收益上限。

当前固定对照数据中，受 `MyGarrisonEffectsAfterExit` 来源在场规则影响的有以下五组、十份普通／精锐配置；其中获授特质还须由独立的保留开关保留下来：

| 持有者或来源 | 触发与普通／精锐效果 |
| --- | --- |
| 魔王（`garrison_59_a/b`） | 身前干员因特质加层时，额外 +1／+2 层。 |
| 莫斯提马（`garrison_22_a/b`） | 周围四格干员每消耗 6 发弹药，已激活的拉特兰 +1／+2 层。 |
| 初雪、银灰（`garrison_28_a/b`） | 范围内敌人进入冻结时，50% 概率使已激活的谢拉格 +1／+2 层。 |
| 凛御银灰授予前方谢拉格干员的特质（`garrison_29_a/b`） | 范围内敌人进入冻结时，60% 概率使已激活的谢拉格 +1／+2 层。普通配置另有 200 层的每场基础收益上限。 |
| 缇缇（`garrison_125_a/b`） | 范围内敌人或干员进入沉睡／晕眩时，已激活的萨尔贡、精准各 +1／+2 层；各盟约每场基础收益上限 24／48 层。 |

凛御银灰自身的 `garrison_126_a/b` 在开战时完成授予；此后的退场判断针对接受特质的干员，授予者退场不会撤回已经完成的授予。

`PositionMode()`、`GarrisonEffectsAfterExit()` 和 `RetainGrantedGarrisonsAfterExit()` 提供整局与战场的只读设置。自定义盟约／技能使用 `Battle::RulePosition`、`RuleRange`、`RuleRangeKeys` 和 `InRuleRange` 查询，让来源与友方目标采用同一位置基准；范围缓存保留朝向、扩展和原始格顺序，地图边界处从原始偏移重新构建。无来源单位的绝对格触发区域继续按显式坐标处理。

敌人的移动与受击位置、阻挡、地形和弹道路径保持实时。普通攻击使用实时射程；活动技能的攻击、治疗和额外治疗按所选规则索敌，瞬发技能的弹道在发射时记录位置模式。普通主动技能的退场结束、生命恢复和攻击生命周期继续执行原规则；两个退场选项分别控制战斗特质的来源在场限制与获授特质的保留。项目当前提供 C++ 宿主入口，设置界面与网络协议尚未实现。

## 战略准备效果

`ReferencePreparationBands()` 生成 21 类准备规则、44 份参数记录。`ChoiceRewardPlayerConfig::MyStrategy` 选择玩家战略；`PreparationContent` 借用静态规则，在收入、回合开始、准备结束、价格、购买、刷新、升级、出售和消费后执行静态分派。`LocalMatch` 已自动安装。铃兰的特质重触发已接入；鸭爵的波次改写、战斗战略及地图战略另计。

带战略的调用方使用 `PreparationContent::BeginRound(round, random)` 发放收入，再调用 `OnRoundStart(random)`；准备结束使用 `OnPreparationEnd(random)`，最后关闭经济准备阶段。`PriceOf(player, slot)` 返回实时支付价格，经济私有视图中的商店价格仍是基础价格。不能用基础价格替代购买校验。计数和随机流与经济事务一同提交，失败命令不消费首购折扣或随机流；重复准备结束被拒绝。

## 支援干员与首批 DIY 共有机制（待统一验证）

补位和自选配置以实际 `charId` 选择处理器，不沿用被替换棋子的专属逻辑。配置生成时保存基础天赋、所选技能和模组数据，运行时使用静态参数。条件属性处理器共用部署延时、范围人数、邻格人数、独处、阻挡和生命比例条件；不同采样周期保持原规则。

每次攻击拥有独立编号，主目标、多段、溅射、连锁及弹道保存相同编号。Raidian 的命中率判定在其他伤害回调之前执行，一次失败取消该攻击的全部伤害回调；Stormeye 使用编号识别各目标的首段生命比例检查。Misery 的拉动先经过独立零伤害命中，并在该组命中完成后统一执行。

独立屏障按生成顺序吸收并分别计时，附属属性增益由同类屏障共同持有，最后一道屏障移除或到期时清理。范围光环共用静态属性组合、职业筛选、地面额外属性和同名强度判定。止颂技能先执行异常状态下的自身法术伤害，再清除异常；存活时才应用技能生命增益。夜莺幻影库存与技能召唤库存分开，在收费重部署成功时扣除。
